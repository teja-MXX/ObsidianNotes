# 🚨 Introduction

## 🧠 **Definition of Security Incident**

A **Security Incident** is:

> “Any event or action that has a negative consequence on the security of a user, computer, or an organization.”

Here are the below listed examples

## ⚠️ Examples of Security Incidents

- 💥 Crashing the system (e.g., kernel panic, blue screen)
- 🦠 Execution of unwanted/malicious program
- 🔓 Unauthorized access to sensitive data
- 🖼️ Website defacement
- 🔌 USB device usage despite restriction (violates org policy)
    
## 🎯 Learning Objectives

### 🕵️ OSINT for Investigation

- Use OSINT (Open Source Intelligence) to:
    - Investigate suspicious IPs, hashes, domains
    - Enrich log context with threat intelligence
    - Examples: VirusTotal, AbuseIPDB, Shodan, Hybrid Analysis
        
### 🧬 Cyber Kill Chain Mapping

- Track attacker behavior across the **Cyber Kill Chain**:
    
    1. **Reconnaissance**
    2. **Weaponization**
    3. **Delivery**
    4. **Exploitation**
    5. **Installation**
    6. **Command and Control (C2)**
    7. **Actions on Objectives**
        

> This helps determine attack **stage** and anticipate **next move**

Next defining Splunk Mastery
### 🔍 Splunk Search Mastery

- Use Splunk to query and correlate logs:
    
    - Search for Event ID `4625` → Failed Login Attempts
    - Search for suspicious processes `New_Process_Name=whoami`
    - Analyze DNS logs for domain beaconing
    - Use regex/wildcards to hunt anomalies
        
> A well-formed search can **speed up investigation** and reduce MTTD (Mean Time to Detect)

And . . . . 
### 🧭 Host-Centric vs Network-Centric Logs

|Type|Description|Examples|
|---|---|---|
|🖥️ Host-Centric|Logs generated on endpoints|Sysmon, Windows Event Logs, osquery|
|🌐 Network-Centric|Logs from network interactions|Firewall logs, VPN logs, DNS, proxy|

## 🧠 Pro Tip: Combine both log types for complete visibility

Example:
- Detects successful `RDP login` (host)
- Detects `port scan` or `beaconing` (network)

# 🧠 Incident Handling Life Cycle

> As a SOC Analyst or Incident Handler, understanding the **Incident Handling Life Cycle** is critical to effectively respond to and learn from security incidents. This lifecycle helps detect, respond, contain, and prevent future attacks by mapping them to clearly defined phases.

Here are the phases in incident handling lifecycle
## 1. 🛠️ Preparation

**Goal:** Ensure the organization is ready to handle incidents before they happen.

**Key Activities:**
- Define security policies, procedures, and incident response plans.
- Deploy preventive tools (EDR, SIEM, IDS/IPS, firewalls).
- Regularly test and update incident response playbooks.
- Conduct employee awareness and SOC team training.
- Establish communication and escalation channels.
    
## 2. 🔍 Detection and Analysis

**Goal:** Detect incidents early and understand what’s happening.

**Key Activities:**
- Ingest and correlate logs using SIEM, EDR, and threat intel feeds.
- Monitor for alerts, anomalies, and suspicious patterns.
- Identify indicators of compromise (IOCs) and initial access vector.
- Triage and validate alerts (True vs. False positives).
- Document root cause and affected systems/users.
    
## 3. 🚨 Containment, Eradication, and Recovery

**Goal:** Stop the spread, remove the threat, and bring systems back to normal.

**Key Activities:**
- **Containment:** Isolate infected systems or networks to prevent lateral movement.
- **Eradication:** Remove malware, kill malicious processes, revoke credentials.
- **Recovery:** Restore from clean backups, reimage machines, and monitor for re-infection.
- Apply additional controls like patching, blocking IPs/domains, etc.

## 4. 📚 Post-Incident Activity / Lessons Learnt

**Goal:** Learn from the incident to improve future response and reduce risk.

**Key Activities:**
- Conduct a post-mortem or after-action review (AAR).
- Identify what worked and what didn’t.
- Update playbooks, SIEM correlation rules, and detection signatures.
- Patch vulnerabilities exploited in the attack.
- Provide retraining where gaps were found (human error, slow detection, etc.).
- Communicate findings with stakeholders and compliance teams.
    
## 🧾 Real-Life Story: WannaCry Ransomware in a Healthcare Setting

In 2017, a **mid-sized hospital** experienced a massive disruption due to the **WannaCry ransomware** outbreak.

### 🔁 Mapped to the Lifecycle:

**Preparation:**  
They had basic defenses like antivirus and firewalls, but **no patching policy**, **SMBv1 was enabled**, and **staff lacked training**. No incident response drills had been conducted.

**Detection and Analysis:**  
Their EDR and SIEM started flagging unusual file encryption and SMB traffic. Analysts discovered the infection vector was **EternalBlue** exploit (MS17-010). Multiple systems were affected in minutes.

**Containment, Eradication, and Recovery:**

- Infected systems were disconnected from the network.    
- Clean images were deployed.
- SMBv1 was disabled and urgent patches were applied.
- Systems were restored using off-site backups, minimizing data loss.
    
**Post-Incident:**

- A security audit was performed.
- Patch management was implemented.
- Staff were trained to recognize ransomware behavior.
- New correlation rules were added in the SIEM to detect similar patterns in the future.
    
> **Lesson:** A lack of preparation amplifies the damage. Even a simple vulnerability like SMBv1 can cripple operations if not managed proactively.
